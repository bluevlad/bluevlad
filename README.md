## AI-Driven Self-Evolving Operations Framework

> A heterogeneous service fleet that **inspects itself · repairs itself · learns from itself**. Five named AI agents form a closed loop — operations feed observation, observation feeds inspection, inspection feeds repair, repair feeds insight synthesis, insight synthesis feeds the next cycle of operations. Each cycle leaves the platform measurably better than before.

### Inside Each Agent

#### 🔍 QA-Agent — *Inspects every service nightly*

A remote QA PC (Windows) runs Playwright E2E/API across the active service fleet at the late-night slot. Findings are **Git-verified, origin-tagged** (regression / new-feature / external-tech adoption), and committed to GitHub Issues with the `qa-agent` label. RAG quality is evaluated on chatbot endpoints. Verified fixes are auto-closed.

> 🎯 **Operator sees** → labeled Issues with reproduction trace. **Decides** → which to fix this cycle.

#### 🤖 Auto-Tobe-Agent — *Fixes and enhances autonomously*

**Dual-engine** — Claude Code CLI (Opus) for complex multi-layer fixes on hopenvision / AllergyInsight / NewsletterPlatform; an Ollama ReAct loop (qwen2.5-coder:14b) for unmong-main / StandUp at zero cost. Auto-fallback to Claude on local-engine failure. Output is a PR with a fix-compliance footer (Discovery-Method · Root-Cause · Recurrence · Prevention) — the same footer feeds the QA Dashboard's prevention-model dataset, so **every fix becomes training data for the next cycle**.

> 🎯 **Operator sees** → PR with rationale + risk note. **Decides** → merge.

#### 📡 InfraWatcher — *Single pane for the whole fleet*

Real-time Docker telemetry over WebSocket — CPU / memory / health-check / restart counts across the multi-subdomain operations fleet. **Auto-recovery on health-check failure**, time-series analytics for rolling-deploy regression detection, container-action surface (start / stop / restart / logs) gated by Google-OAuth admin. From any browser, the operator can observe and intervene anywhere on the fleet.

> 🎯 **Operator sees** → live state of every container, anywhere. **Decides** → manual intervention only when auto-recovery exhausts retries.

#### ✍️ StandUp — *Weekly synthesis that gets smarter every week*

Pulls from three internal operations sources (LogAnalyzer error patterns · GitHub QA issues · Auto-Tobe fix journal) into a canonical event store keyed by `content_hash UNIQUE`. A **three-stage local LLM cascade** — `llama3.2:3b` summarizes batches → `qwen2.5-coder:14b` extracts JSON insight → `EXAONE 3.5 7.8B` composes Korean prose (deliberate Korean-first choice over llama3.3:70b under 24GB MacBook constraint; A/B vs Qwen/Gemma logged). Stage latency 8s + 40s + 40s ≈ 100–150s end-to-end. The sent newsletter is **re-indexed into a pgvector self-referencing corpus (4 collections: corpus_qa / corpus_logs / corpus_fixes / corpus_newsletters)**, so each new edition compares against past patterns and the suggestion quality improves week over week. Every body claim renders as `[REF:url]` back to the original Issue / log group / commit. `STANDUP_MODE` (legacy / both / insight) gives zero-redeploy rollback.

**Recent advances (2026-Q2)** — *Insight Dashboard 0.6.0* exposes post-send visibility (Tech Digest timeline · pgvector-cosine + union-find topic clustering · HopenVision LLM proposals auto-drafted as DevPlans). *HopenTechBrief 0.7.0* (2026-05-08) routes medium-digest-agent reports through a 60-point stack-fitness gate (stack-match 0–60 + LLM relevance 0–40) into 7-box card-mail with Mermaid As-Is/To-Be and PoC code hints. *Claude session-log federation 0.8.0* (2026-05-13) — 4-table schema with Stop hook, qwen2.5:7b auto-summarization, API key/JWT/email masking, and a 1-click `open → registered` work-item gate brings dev-discussion context into machine-readable tracking.

> 🎯 **Operator reads** → weekly Korean briefing with cited sources and a *new tech to adopt* recommendation; daily HopenTechBrief curation. **Decides** → which suggestion to act on — grounded in last week's actual ops events, not a generic trend feed.

#### 🧬 AllergyInsight RAG — *Knowledge base that learns daily*

A daily ingestion pool runs across PubMed · Semantic Scholar · Europe PMC · OpenAlex · bioRxiv/medRxiv · ClinicalTrials.gov · CORE · Naver/Google News · openFDA · MFDS, into a single canonical store with three-stage dedup (URL-canonical + content + MinHash). **Dual-surface** — the same store productizes into the `allergy-insight` tenant on NewsletterPlatform (daily 4-section clinical briefing) **and** seeds the `/ai/consult` chatbot's per-allergen ChromaDB RAG. Five anonymous public pages cover MAST class · symptom free-text · RAG chatbot · allergy-related ATC drug groups · PMC-OA clinical image gallery — with diagnosis-disallowed phrasing, citation + license on every response, and emergency-keyword bypass routing to 119. Bounce feedback loop (IMAP NDR scrape, RFC 3464 DSN parsing) auto-deactivates hard-bounced addresses across all tenants.

**Recent advances (2026-Q2)** — *Vertical Insight Framework (ADR-011, 2026-05-11)*: 4-layer domain abstraction (`core/sources` + `core/domains` + DomainPack YAML v1 + 13-rule pack linter) lets a new medical domain attach via YAML + prompts with zero `core/` code changes — dermatology fixture verified with 31 passing unit tests. *Source Connector Registry*: PaperSourceConnector / NewsSourceConnector / RegulatorySource ABC + `NormalizedDoc`, with PMID/DOI cross-lookup helpers. *Strategic Intel v1* (Phase A–E, 2026-05-05): rule+LLM hypothesis engine across 4 Korean IVD companies × 10 tech categories, validated against abnormal returns + 60-day volume z-score (Wilson CI + binomial test); 5 signal sources (DART · FDA 510(k) · ClinicalTrials.gov · PubMed IVD · news) + IP-hash audit logging + report watermarking. *Newsletter section redesign* (2026-04-16): category buckets → impact-based ordering (Top 5 Headlines · Industry Trends · Drug Updates · PubMed Papers) with MinHash ≥ 0.90 + 1-per-company + headline-disjoint constraints.

> 🎯 **Operator curates** → which corpora, which allergens, which domain packs. **The platform** → grows its domain vocabulary every day, no retraining needed; new verticals attach without touching the core.

> ⏸️ **Phase 5** — clinical B2B module on hold pending kit-manufacturer partnership; legacy modules disabled by `LEGACY_MODULES_ENABLED=false` for back-channel reactivation.

#### 📧 NewsletterPlatform — *Multi-tenant delivery, hardened by real incidents*

Four tenants — `allergy-insight` · `standup` · `edufit` · `tech_briefing` — run on a shared core with a `BaseTenant` abstraction (`collect_summary_data` · `extract_sent_article_entries` · `dedup_recent_days`). API-driven collection (no direct DB access across tenants) prevents coupling; a standard 10-step `TENANT_ONBOARDING.md` checklist replaced the ad-hoc migration that AllergyInsight v1 went through.

**Recent advances (2026-Q2) — four production incidents and one attack response shaped the current platform.** *(1)* **Stale-cache admin alert (ADR-004, 2026-05-13)** — a 5/12–5/13 incident (OrbStack `NO_PROXY` IPv6 CIDR parsing broke `httpx.AsyncClient` creation) caused 3 days of identical content to subscribers. The fix is structural: a 24h cache threshold blocks general send and routes `send_mode='stale_admin_alert'` to super-admins only with a `[⚠️STALE]` banner — the new send_mode prevents dedup-pool pollution, the same pattern as `weekend_test` mode. *(2)* **Article-level dedup pipeline (P1–P3, 2026-04-20)** — `sent_articles(tenant_id, article_id, section, sent_date)` with UNIQUE constraint plus `exclude_ids` POST alias (URL-length-safe at 400+ IDs) blocks 7-day same-article repeats at the SQL layer. *(3)* **3-tier send slots (2026-04-30)** — single 5:00 KST collect feeds 6:40 / 7:40 / 8:40 send slots; shared cache yields 100% content parity across slots with 1/3 API-call reduction. *(4)* **Subscription-abuse hardening (P0–P3, 2026-05-02~06)** — Cloudflare Turnstile + IP/email rate-limits (5/h IP · 1/min email · 3/day email) + honeypot + role-account regex + bot-name pattern detector; P0 removed a plaintext admin default password from the public repo. *(5)* **Two new tenants** (2026-05-08) — TechBriefing Daily (signal-based importance: tier_weight + source_weight + CVSS boost + breaking boost − age penalty, LLM-free) and StandUp Weekly Insight (KPI-first 7-section template). *(6)* **F/E/L 3-axis improvement plan v2** — Freshness ✅ complete · Efficacy 7-day window A/B (3/5/7-day buckets, conditional early stop at +20% unsubscribe) · Learning subscriber-feedback UI (👍/👎/"tell me more" with HMAC-signed click tokens, flag-gated, cold-start-safe).

> 🎯 **Operator sees** → admin alert when cache goes stale, per-slot statistics, abuse-attack telemetry, tenant-isolated bounce metrics. **Decides** → which tenant to onboard next (the framework now scales to N).
